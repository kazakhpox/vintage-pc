# Vintage PC — компьютер из 2000-х для Minecraft (NeoForge 1.21.1)

Блок «Ретро-компьютер». Правый клик включает ПК: внутри Chromium (MCEF) запускается оболочка в стиле Windows 98. Игры подключаются как «картриджи» — отдельные папки.

Управление:
- **Shift+Esc** — отойти от ПК. Обычный Esc остаётся играм.
- **F8** — взять или отдать управление (hotseat).
- Если игрока ударили, экран ПК закрывается.

## Архитектура

```
┌──────────────────────────── клиент игрока ────────────────────────────┐
│ MCEF (Chromium) ── http://127.0.0.1:PORT ──► LocalHttpServer (в моде) │
│   оболочка /web/*           ← из jar                                  │
│   движки   /engines/*       ← из jar (или замена в vintagepc/engines) │
│   картриджи /carts/<id>/*   ← с диска, Range-запросы                  │
│   сеть     ws://…/lan       ← LanBridge ──► пакеты Minecraft ─────┐   │
└───────────────────────────────────────────────────────────────────┼───┘
                                    сервер Minecraft:  LanHub (L2-свитч) + PcSessions (hotseat)
```

**Почему локальный HTTP-сервер, а не `file://`.**
- Chromium не даёт делать `fetch()` и стриминг WASM с `file://`, а без этого js-dos, v86 и Emscripten-порты не запускаются.
- Заголовки COOP/COEP включают `crossOriginIsolated`, а с ним SharedArrayBuffer. Это нужно многопоточным WASM-портам (reVC, Xash3D).
- Образы дисков на гигабайты читаются кусками через Range-запросы и не загружаются в память целиком.
- Сервер слушает только loopback, проверяет заголовок `Host` и требует секретный токен в HttpOnly-cookie.

### Картриджи — игры отдельными папками
Мод их не включает: это ваши лицензионные копии. Папка: `.minecraft/vintagepc/cartridges/<id>/` с файлом `cartridge.json`. Рабочий стол подхватывает их автоматически.

```jsonc
// DOS-игра: просто положите файлы игры рядом — мод сам соберёт .jsdos-бандл (и пересоберёт при изменениях)
{ "name": "Warcraft II", "icon": "⚔️", "engine": "jsdos",
  "net": { "mode": "ipx" },
  "jsdos": { "cycles": "max", "autoexec": ["cd WAR2", "WAR2.EXE"] } }
// или готовый бандл: "jsdos": { "bundle": "game.jsdos" }

// Windows 98 в эмуляторе x86
{ "name": "Windows 98", "engine": "v86",
  "v86": { "hda": "win98.img", "memory": 128, "async": true } }   // также cdrom, fda, state, boot_order

// WASM-порт (reVC, Xash3D-FWGS, ioquake3…)
{ "name": "GTA: Vice City", "engine": "html", "html": { "entry": "index.html" } }
```

## Физическая сеть: кабели и роутер

Компьютеры соединяются в сеть только проводами, проложенными в мире:

| Блок | Рецепт | Что делает |
|---|---|---|
| **Сетевой кабель** ×16 | нитки + медь + редстоун | Сам соединяется с кабелями, ПК и роутерами (как провод). Один отрезок — не длиннее **100 блоков**. |
| **Роутер** | громоотвод + кварц + повторитель + железо | Объединяет всё подключённое в одну сеть и работает как повторитель. Пока идут пакеты, мигают светодиоды. Имя сети задаётся переименованием на наковальне. ПКМ — сведения о сети. |

- Компьютер — оконечное устройство: сеть через него не проходит.
- Два ПК, соединённые кабелем напрямую, работают без роутера (кроссовер). Для трёх и больше нужен роутер.
- Сервер раз в секунду обходит провода и сообщает каждому включённому ПК, к какой сети тот подключён. Мост клиента дописывает к именам каналов идентификатор этой сети, а сервер пускает игрока в канал, только если у него есть ПК, физически подключённый к ней. Изолированные сети не видят друг друга, и обойти это из браузера нельзя.
- Если кабель перерезать, ПК сразу теряет сеть. В трее появляется значок 🖧❌ и подсказка «Сетевой кабель не подключён», как в Windows.

## Сетевая игра на сервере Minecraft

Сервер Minecraft работает как **обучаемый L2-коммутатор**. Hamachi, VPN и открытые порты не нужны. Каждая физическая сеть (роутер или прямой кабель) — отдельный сегмент. Адресные пакеты коммутатор отправляет только получателю, а не всем игрокам.

| Способ | Игры | Как устроено |
|---|---|---|
| **IPX (js-dos)** | Heroes II, Red Alert, Warcraft II, Doom, Duke 3D | В js-dos 8 сеть подключаемая (`sharedNet`). Мод подставляет свой бэкенд `VPCNet.humbleNet`: IPX-пакеты DOSBox идут кадрами Ethernet через коммутатор. В плеере есть лобби: «Создать игру» или «Подключиться к …». |
| **Ethernet (v86)** | Windows 9x/DOS в эмуляторе, любые IPX- и TCP/IP-игры | Сетевая карта NE2000 эмулятора подключена к тому же сегменту. |
| **UDP** | WASM-порты (Quake III — 27960, Xash3D/CS — 27015) | `VPCNet.udp(net, port, cb)` собирает настоящие IPv4/UDP-кадры с адресом `10.98.x.y` и отвечает на ARP. Сетевой слой порта нужно направить в этот API — см. ниже. |
| **Doom (doom-wasm)** | Freedoom | Протокол ретранслятора Cloudflare (`[кому][от кого]` → `[от кого]`) переложен на Ethernet-кадры (0x88B7, MAC из uid). У каждой партии свой сегмент `<группа>.doom.<хост>`. |
| **Комнаты** | JS-игры, чат, лобби | `VPCNet.room(name)` — JSON-сообщения всем участникам. Пример: крестики-нолики. |
| **Монитор в мире** | все | Экран включённого ПК виден прямо на блоке: хосту — напрямую из Chromium, игрокам в радиусе 24 блоков — потоком 2 к/с. |
| **Hotseat** | Heroes III, Worms и любая другая игра | Один ПК, остальные игроки рядом смотрят его экран (JPEG ~6 к/с, около 15 КБ на кадр, неизменный экран не передаётся). По **F8** игроки по очереди берут управление. Зрителю MCEF не нужен. |

Ограничения сервера (защита от флуда):
- 200 пакетов и 256 КБ сети за тик на игрока;
- 96 КБ кадров экрана за тик на ПК;
- 40 событий ввода за тик;
- зритель должен стоять не дальше 8 блоков от ПК.

### Подключение сети WASM-порта
В HTML-обёртке порта подключите `/web/vpc-net.js` и замените отправку и приём UDP:

```js
const sock = VPCNet.udp(VPCNet.net, 27960, (p) => portRecv(p.srcIp, p.srcPort, p.data));
function portSend(ip, port, bytes) { sock.sendto(ip, port, bytes); }   // '255.255.255.255' — поиск серверов в LAN
```

## Сборка и запуск

```bash
./gradlew build
```

Для проверки сети запустите сервер и два клиента:

```bash
./gradlew runServer
```
```bash
./gradlew runClient
```
```bash
./gradlew runClient2
```

MCEF — `com.cinemamod:mcef-neoforge:2.1.6-1.21.1`. Это необязательная зависимость: без MCEF можно только смотреть чужой экран.
