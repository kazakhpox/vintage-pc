# Vintage PC — компьютер из 2000-х для Minecraft (NeoForge 1.21.1)

Блок «Ретро-компьютер». Правый клик включает ПК: звучит писк BIOS, раскручивается вентилятор, щёлкает жёсткий диск и играет стартовый аккорд. Камера плавно подлетает к монитору. Интерфейс в стиле Windows 98 (Chromium через MCEF) показывается прямо на экране монитора в мире: формат 4:3, рамка — корпус старого ЭЛТ, вокруг виден мир. Игры подключаются как «картриджи» — отдельные папки.

Управление:
- **Shift+Esc** — отойти от ПК. Обычный Esc остаётся играм.
- **F8** — взять или отдать управление (hotseat).
- Если игрока ударили, экран ПК закрывается.

## Архитектура

```
┌──────────────────────────── клиент игрока ────────────────────────────┐
│ MCEF (Chromium) ── http://127.0.0.1:PORT ──► LocalHttpServer (в моде) │
│   оболочка /web/*           ← из jar                                  │
│   движки   /engines/*       ← из jar (или замена в vintagepc/engines) │
│   картриджи /carts/<id>/*   ← с диска, Range-запросы                  │
│   сеть     ws://…/lan       ← LanBridge ──► пакеты Minecraft ─────┐   │
└───────────────────────────────────────────────────────────────────┼───┘
                                    сервер Minecraft:  LanHub (L2-свитч) + PcSessions (hotseat)
```

**Почему локальный HTTP-сервер, а не `file://`.**
- Chromium не даёт делать `fetch()` и стриминг WASM с `file://`, а без этого js-dos, v86 и Emscripten-порты не запускаются.
- Заголовки COOP/COEP включают `crossOriginIsolated`, а с ним SharedArrayBuffer. Это нужно многопоточным WASM-портам (reVC, Xash3D).
- Образы дисков на гигабайты читаются кусками через Range-запросы и не загружаются в память целиком.
- Сервер слушает только loopback, проверяет заголовок `Host` и требует секретный токен в HttpOnly-cookie.

**CS 1.6** — в мод входит только открытый движок, без данных Valve. Положите `valve.zip` из своей копии игры (папки `valve/` и `cstrike/` в корне архива) в `.minecraft/vintagepc/cartridges/cs16/`. Статус «бета»: проверено, что движок и файловая система запускаются, а игровой процесс и сетевая игра без данных игры не проверены.

**Чего в моде нет и почему:**
- **GTA: Vice City (reVCDOS).** Он загружает данные Rockstar с нелицензированных зеркал, а сам движок reVC снимали через DMCA.
- **Wargus.** Нативная программа на движке Stratagus без браузерной сборки. Вместо неё Warcraft II для DOS из своей копии можно запустить картриджем js-dos, IPX по сети работает.

При первом запуске встроенные игры копируются из jar в `vintagepc/cartridges/`. Если игрок удалит такую папку, она больше не вернётся.

### Картриджи — игры отдельными папками
Мод их не включает: это ваши лицензионные копии. Папка: `.minecraft/vintagepc/cartridges/<id>/` с файлом `cartridge.json`. Рабочий стол подхватывает их автоматически.

```jsonc
// DOS-игра: просто положите файлы игры рядом — мод сам соберёт .jsdos-бандл (и пересоберёт при изменениях)
{ "name": "Warcraft II", "icon": "⚔️", "engine": "jsdos",
  "net": { "mode": "ipx" },
  "jsdos": { "cycles": "max", "autoexec": ["cd WAR2", "WAR2.EXE"] } }
// или готовый бандл: "jsdos": { "bundle": "game.jsdos" }

// Windows 98 в эмуляторе x86
{ "name": "Windows 98", "engine": "v86",
  "v86": { "hda": "win98.img", "memory": 128, "async": true } }   // также cdrom, fda, state, boot_order

// WASM-порт (reVC, Xash3D-FWGS, ioquake3…)
{ "name": "GTA: Vice City", "engine": "html", "html": { "entry": "index.html" } }
```

## Сборка компьютера

1. Поставьте **корпус ретро-компьютера** (монитор встроен): железо ×8 + стеклянная панель.
2. ПКМ с компонентом в руке вставляет его в корпус. Первой ставится **материнская плата**, затем **процессор, ОЗУ, видеокарта, жёсткий диск и блок питания**. **Wi-Fi-карта** — по желанию.
3. Когда всё на месте, корпус светится индикатором питания, и ПКМ включает компьютер. Без какого-то компонента в строке действий появится «Не хватает: …».
4. Shift+ПКМ пустой рукой вынимает последний вставленный компонент (материнская плата вынимается последней). Если разобрать работающий ПК, он выключится. Если сломать корпус, все компоненты выпадут.

## Физическая сеть: кабели, роутер, Wi-Fi

| Блок | Рецепт | Что делает |
|---|---|---|
| **Сетевой кабель** ×16 | нитки + медь + редстоун | Кладётся на пол, как редстоун: тянется к соседним кабелям и устройствам, поднимается на блок и спускается с него. Один отрезок — не длиннее **100 блоков**. |
| **Роутер** | громоотвод + кварц + повторитель + железо | Объединяет всё подключённое в одну сеть и работает как повторитель. Пока идут пакеты, мигают светодиоды. Имя сети задаётся переименованием на наковальне. |
| **Вышка Wi-Fi** | основание + 4–24 секции мачты + антенна (снизу вверх) | Собранная вышка (основание светится) создаёт беспроводную сеть. К ней подключается любой ПК с Wi-Fi-картой в этом измерении, на любом расстоянии: «Пуск → Беспроводная сеть». Если основание соединить кабелем с роутером, беспроводные ПК попадают в ту же проводную LAN. |

- Компьютер — оконечное устройство: сеть через него не проходит.
- Два ПК, соединённые кабелем напрямую, работают без роутера. Если подключены и кабель, и Wi-Fi, приоритет у кабеля.
- Перед монитором нужна свободная клетка (без твёрдого блока): камера подлетает к экрану, и с блоком перед ним сесть за ПК нельзя.
- **Непрогруженные чанки не мешают.** Кабели, ПК, роутеры и вышки записываются в граф сети, который хранится вместе с миром (`SavedData`). Сервер обходит провода по этому графу и не загружает чанки, поэтому кабель через половину карты и вышка на другом конце света продолжают работать.
- Мост клиента дописывает к именам каналов идентификатор сети, а сервер пускает игрока в канал, только если у него есть включённый ПК, подключённый к этой сети. Изолированные сети не видят друг друга.
- В трее ПК значок показывает, как он подключён: 🖧 — кабель, 📶 — Wi-Fi, ❌ — нет сети, и всплывает подсказка, как в Windows.

## Сетевая игра на сервере Minecraft

Сервер Minecraft работает как **обучаемый L2-коммутатор**. Hamachi, VPN и открытые порты не нужны. Каждая физическая сеть (роутер или прямой кабель) — отдельный сегмент. Адресные пакеты коммутатор отправляет только получателю, а не всем игрокам.

| Способ | Игры | Как устроено |
|---|---|---|
| **IPX (js-dos)** | Heroes II, Red Alert, Warcraft II, Doom, Duke 3D | В js-dos 8 сеть подключаемая (`sharedNet`). Мод подставляет свой бэкенд `VPCNet.humbleNet`: IPX-пакеты DOSBox идут кадрами Ethernet через коммутатор. В плеере есть лобби: «Создать игру» или «Подключиться к …». |
| **Ethernet (v86)** | Windows 9x/DOS в эмуляторе, любые IPX- и TCP/IP-игры | Сетевая карта NE2000 эмулятора подключена к тому же сегменту. |
| **UDP** | WASM-порты (Quake III — 27960, Xash3D/CS — 27015) | `VPCNet.udp(net, port, cb)` собирает настоящие IPv4/UDP-кадры с адресом `10.98.x.y` и отвечает на ARP. Сетевой слой порта нужно направить в этот API — см. ниже. |
| **Doom (doom-wasm)** | Freedoom | Протокол ретранслятора Cloudflare (`[кому][от кого]` → `[от кого]`) переложен на Ethernet-кадры (0x88B7, MAC из uid). У каждой партии свой сегмент `<группа>.doom.<хост>`. |
| **Комнаты** | JS-игры, чат, лобби | `VPCNet.room(name)` — JSON-сообщения всем участникам. Пример: крестики-нолики. |
| **Монитор в мире** | все | Экран включённого ПК виден прямо на блоке: хосту — напрямую из Chromium, игрокам в радиусе 24 блоков — потоком 2 к/с. |
| **Hotseat** | Heroes III, Worms и любая другая игра | Один ПК, остальные игроки рядом смотрят его экран (JPEG ~6 к/с, около 15 КБ на кадр, неизменный экран не передаётся). По **F8** игроки по очереди берут управление. Зрителю MCEF не нужен. |

Ограничения сервера (защита от флуда):
- 200 пакетов и 256 КБ сети за тик на игрока;
- 96 КБ кадров экрана за тик на ПК;
- 40 событий ввода за тик;
- зритель должен стоять не дальше 8 блоков от ПК.

### Подключение сети WASM-порта
В HTML-обёртке порта подключите `/web/vpc-net.js` и замените отправку и приём UDP:

```js
const sock = VPCNet.udp(VPCNet.net, 27960, (p) => portRecv(p.srcIp, p.srcPort, p.data));
function portSend(ip, port, bytes) { sock.sendto(ip, port, bytes); }   // '255.255.255.255' — поиск серверов в LAN
```

## Проверка при задержках

Сетевые игры проверены через коммутатор с искусственной задержкой: пинг игрока, ожидание тика сервера Minecraft (до 50 мс) и джиттер, порядок пакетов сохраняется, как в TCP.

| Профиль | Время «игрок → игрок → игрок» | Freedoom (дезматч на двоих) | DOS IPX (js-dos) |
|---|---|---|---|
| средний пинг (80 ± 15 мс) | ~200 мс | играется, без рассинхронизации | подключение и обмен пакетами работают |
| почти высокий (200 ± 40 мс) | 400–500 мс | играется, без рассинхронизации и разрывов | работает |

При высоком пинге в Doom заметна задержка управления: Chocolate Doom синхронизирует игроков пошагово (lockstep), это свойство самой игры.

```

```

```

```
